# Milestone v0.4.0 — Harness Optimizations

**Status:** planned · **Created:** 2026-08-01 · **Owner:** unassigned

## Purpose

Upgrade fleetsmith's generated harnesses with the platform features and research-backed techniques verified in August 2026 research. Two evidence documents in this repo are the foundation — read both before starting any task:

- `docs/research/platform-optimizations-2026-08.md` — verified current feature surface of Claude Code (v2.1.219), opencode (anomalyco/opencode dev), and goose (aaif-goose/goose main), including 8 breaking changes (B1–B8).
- `docs/research/harness-best-practices-2026-08.md` — cross-platform harness-engineering evidence (context engineering, orchestration, cost, reliability, skill design, evals) with source grades.

**Theme:** the research shows the failure surface of a multi-agent harness is the *handoff contract and role decomposition* (MAST: ~79% of failures), and the cost surface is *cache stability + model tiering* (~10× cached-vs-uncached). v0.4.0 makes fleetsmith emit enforced contracts instead of prose conventions, and cost-tiered agents on all three targets instead of Claude Code only.

## Orientation for an agent/human with zero prior context

fleetsmith (this repo) is a compiler: `fleet.yaml` (tool-agnostic spec) → native agent harnesses for three tools. Key source files:

| Path | Role |
|------|------|
| `src/spec/schema.js` | Normalizes raw fleet.yaml into canonical shape (defaults) |
| `src/spec/validate.js` | Semantic validation (errors block build; warnings advise) |
| `src/adapters/claude-code.js` | Emits `.claude/agents/*.md`, `.claude/skills/*/SKILL.md`, CLAUDE.md pointer |
| `src/adapters/opencode.js` | Emits `.opencode/agents/*.md`, `.opencode/commands/*.md`, AGENTS.md pointer |
| `src/adapters/goose.js` | Emits `.goose/recipes/*.yaml` (agent recipes + orchestrator with sub_recipes) |
| `src/compile/agent-prompt.js` | Tool-agnostic agent prompt body (shared across adapters) |
| `src/compile/orchestrator.js` | Tool-agnostic orchestrator playbook body (invocation section per target) |
| `src/handover/protocol.js` | Handoff file template, ledger template, protocol prompt blocks |
| `src/patterns/index.js` | `fleetsmith init` archetypes per pattern |
| `src/opencode-plugin.js` + `src/opencode.js` | opencode in-session plugin (`fleet_*` tools) |
| `src/cli.js` | CLI (`init`, `validate`, `build`, `install`, `patterns`) |
| `test/fleetsmith.test.js` | `npm test` (node --test) |
| `docs/spec.md` | fleet.yaml reference — update whenever the spec changes |

Conventions: pure ESM, only runtime dep is `yaml`; adapters return `FileSet`s (pure generation, I/O in CLI); every spec change lands in `schema.js` (normalize) + `validate.js` (validate) + `docs/spec.md` (document) + tests. Git: never add a Claude co-author trailer to commits.

## T2 — Spec v0.4 extensions

**Context.** The spec (`src/spec/schema.js`, `docs/spec.md`) lacks fields for the capabilities all three targets now support. Everything added here is normalized with safe defaults so existing fleet.yaml files build unchanged.

**Do.** Add to the normalized spec (schema.js) + validation (validate.js) + docs/spec.md + tests:

1. `agents[].effort` — `minimal|low|medium|high|max`, default absent. Maps: Claude Code `effort` frontmatter (`low|medium|high|xhigh|max` — map `minimal`→`low`); opencode `variant`/`reasoningEffort` passthrough; goose: no native equivalent — omit.
2. `agents[].turns` — positive integer, default absent. Maps: Claude Code `maxTurns`; opencode `steps`; goose `settings.max_turns`. Validator: warn if > 200.
3. `agents[].hidden` — boolean, default false. Maps: opencode `hidden: true`; Claude Code/goose: no-op (documented).
4. `agents[].memory` — boolean, default false. Maps: Claude Code `memory: project`; others: prose note in prompt to keep durable notes in the fleet workspace.
5. `agents[].handoff.schema` — optional JSON-schema object describing the handoff artifact's required fields. Maps: goose `response.json_schema` (native validation); Claude Code/opencode: schema written into the handoff template + validated by the T4 gate script. Default when absent: the four-field brief object (see T11): `{objective, output_format, sources_and_tools, boundaries}`.
6. `phases[].loop` gains `noProgress` (integer, default 2): "stop after N consecutive passes with no progress" — the research-backed second stop rule (best-practices §4.3). `normalizeLoop` returns `{until, max, check, noProgress}`.
7. `skills[].triggers` — optional `{should: [...], shouldNot: [...]}` example prompt lists (consumed by T13). `skills[].freedom` — `high|medium|low` (consumed by skill templates; default `medium`).
8. `fleet.mcp` — optional map `name -> {type, url?, command?, args?}` of MCP servers the fleet needs. Maps: Claude Code `.mcp.json` + per-agent `mcpServers`; opencode `opencode.json` `mcp`; goose recipe `extensions` (`streamable_http`/`stdio`).
9. `agents[].parallelSafe` is NOT added — parallel-write safety is derived (see T12).

**Accept when** all new keys normalize with defaults, are validated, documented in `docs/spec.md` with target-mapping notes, covered by tests, and `npm test` passes. Existing example specs (`fleet.example.yaml`, archetypes) still validate warning-free.

## T12 — Validator/linter: single-writer rule, description budgets, skill anti-pattern lint

**Context.** Best-practices §0.2, §5.2, §5.6, §1.3. All mechanically checkable at build time in `src/spec/validate.js` (or a new `src/spec/lint.js` invoked by validate).

**Do.** Add validations:
1. **Error:** a `parallel: true` phase containing more than one agent with `capabilities.edit: true` and no disjoint-path evidence → error with message citing the single-writer rule (downgrade to warning if `fleet.allowParallelWrites: true`, a new escape-hatch key — add to T2 schema).
2. **Error:** any skill `description` (+ future `when_to_use`) over 1,536 chars; **warning** when the sum of all skill descriptions exceeds ~8,000 chars (proxy for the 1%-of-context listing budget) — message names the platform truncation behavior.
3. **Warnings** (skill lint): body contains `\` -style Windows paths; date-like strings ("before 20XX", month-year patterns) suggesting time-sensitive content; unqualified MCP tool references (`mcp__` without server, or tool names with spaces); reference files >100 lines without a `## Contents`/TOC heading; references linking to further references (depth >1); skill names that are not gerund/noun-phrase (heuristic: warn on `helper`, `utils`, `misc`); first-person description ("I ", "you can ask me").
4. **Warning:** adjacent pipeline phases whose agents share ≥ all incoming artifacts (same `accepts` set) → "context-centric decomposition: consider merging these agents" (best-practices §0.1).
5. **Warning:** loop without `check` (exists) — extend message to say a shell check with exit code is the research-backed form.

**Accept when** each rule has a unit test (positive + negative), `fleet.example.yaml` and archetypes pass clean, and `npm test` passes.
