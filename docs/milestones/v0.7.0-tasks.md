# v0.7.0 Intelligence Grid — Task Breakdown

**Status:** planned · **Created:** 2026-08-15 · **Spec:** `docs/milestones/v0.7.0-intelligence-grid.md`

Sizes: S = ≤ half a day, M = 1–2 days, L = 3–5 days. Every task lists the files it owns; two tasks never own the same file (single-writer, same rule the grid itself uses). Core files are MIT; anything under `ee/` is AGPL-3.0-only.

## Phases

| Phase | Epics | Exit criterion |
|---|---|---|
| P1 Foundation | G0, G1, G2, G3 | Two actors see each other's ledger rows in `grid/peers/` with no commit; `rm -rf ee/` restores v0.6 |
| P2 Intelligence | G4, G5, G6 | Eval fleet passes the overlap scenario; imported meeting notes recallable by purpose on both backends |
| P3 Enterprise | G7, G8 | Approval state machine round-trips CLI → console; audit answers actor/purpose/time from the UI |
| P4 Ship | G9, G10 | Degradation matrix in CI green; both packages published |

## Standing rules for every task

1. **Delete-test:** every ee task must keep `rm -rf ee/` → v0.6-identical true.
2. **No capability ee-only:** each user-visible feature names its degraded core answer in its PR description.
3. **Single-writer rows:** any new grid type must be keyed so no two actors write the same row.
4. **Advisory only:** nothing in this milestone may gate an agent, alter a QA/eval verdict, or write to `_fleet/shared/` outside the PR ladder.
5. **License headers:** SPDX `AGPL-3.0-only` on `ee/src/**`, `MIT` implied elsewhere; CI-checked (G0.4).
