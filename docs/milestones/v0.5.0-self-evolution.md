# Milestone v0.5.0 — Self-Evolving Harness

**Status:** planned · **Created:** 2026-08-04 · **Owner:** unassigned

## Purpose

Make fleetsmith a **self-evolving harness**: a fleet observes its own runs, evaluates outcomes against deterministic gates, proposes typed mutations to its own fleet.yaml / skills / playbooks, validates them on replay, and promotes them through git — with the human reviewing few, ranked, confidence-scored proposals instead of babysitting every change.

Two evidence documents are the foundation — read both before starting any task:

- `docs/research/self-evolving-agents-2026-08.md` — state-of-the-art digest (DGM, GEPA, ACE, SkillOps/SkillMentor/SkillOS, Misevolution, canary promotion, git-as-rollback), with the five-stage loop synthesis and six safety invariants.
- The architectural audit summarized in §"Gap → mechanism map" below (codebase reconnaissance, 2026-08-04).

**Theme:** fleetsmith is already a compiler (`fleet.yaml` → harnesses). v0.5.0 makes it a **self-tuning compiler**: the loop is OBSERVE → EVALUATE → MUTATE → VALIDATE → PROMOTE, where deterministic checks carry every gate, all learned content is append-only id'd bullets (never whole-file rewrites), and git is the archive, review surface, and rollback. We deliberately choose the archive-of-artifacts model (DGM/ADAS) over runtime self-modification (Gödel Agent): every change is a file diff on a branch.

## Orientation for an agent/human with zero prior context

fleetsmith (this repo) compiles `fleet.yaml` (tool-agnostic spec) → native agent harnesses for Claude Code, opencode, and goose. Key source files:

| `src/adapters/claude-code.js` | `.claude/agents/*.md`, `.claude/skills/*/SKill.md`, `.claude/settings.json`, CLAUDE.md pointer |
| `src/adapters/claude-settings.js` | Generates the `SubagentStop` handoff gate (`_fleet/scripts/validate-handoff.sh`) |

| `src/adapters/claude-workflow.js` | Experimental 4th target: phases as code, loops as `while`, structured per-agent results |
| `src/compile/agent-prompt.js` | Shared agent body; **cache-stability invariant at :8-14** (no per-run state in prompts) |

| `src/compile/evals.js` | Per-skill `evals/evals.json` scaffolding (trigger corpora, empty `cases: []`) |

Conventions: pure ESM, only runtime dep is `yaml`; adapters are pure `spec → FileSet` (I/O in CLI); every spec change lands in `schema.js` + `validate.js` + `docs/spec.md` + tests. Git: never add a Claude co-author trailer to commits.

Runtime state lives in `_fleet/` (LEDGER.md, handoffs/, scripts/, notes/). The `SubagentStop` gate is the only deterministic enforcement point and is Claude Code-only; opencode enforces via permission maps, goose via `response.json_schema`.

## Design invariants (non-negotiable, each earned from a documented failure)

1. **Evolution may only modify what evolution generated.** The validator, `harness-qa`, the eval suite, and any `origin: human` artifact are immutable to the loop. Enforced in the patch API and CI, not prose. *(DGM marker-removal hack; Anthropic "unacceptable to edit tests")*
2. **Handoff contracts are rails.** Agent instruction bodies evolve freely; declared `handoff.to/artifact/accepts/criteria/schema` change only via an explicit `contract-change` op that is always human-reviewed. *(Roles with Rails)*
3. **Learned content is advisory, append-only, and visibly machine-authored.** ACE-style id'd bullets with helpful/harmful counters, deterministic non-LLM merge, framed as "references, not rules." *(Misevolution: memory evolution measurably decays safety; references-not-rules was the only mitigation that helped)*
4. **Deterministic checks carry every gate; judges are advisory.** The verifier is the ceiling of the whole system — invest in `validate`/`qa`/`eval` before any LLM judge. *(verifier bottleneck)*
5. **Few, ranked, confidence-scored review requests.** Auto-apply only ops a deterministic validator fully verifies; batch the rest; learn from rejections. *(HITL automation bias)*
6. **Cap evolved artifact length** (500-line SKILL.md bound; per-bullet budget). *(Decagon: 4× compression for 0.8% loss)*
7. **Preserve the cache-stability invariant** (`agent-prompt.js:8-14`): learned state enters prompts only via spec → rebuild, or via read-at-runtime files — never per-run prompt injection.
8. **Git is the archive.** Every mutation is a branch; every promotion a tagged merge; `git revert` is the rollback. Archive members (tags) are parent candidates, not just the best.

## Non-goals for v0.5.0 (deliberate)

- **No runtime self-patching** (Gödel Agent model) — no review surface, no rollback.
- **No OTel dependency** — conventions unstable through 2026; borrow vocabulary only.
- **No general trajectory judge** — one advisory substance judge at most (T9), calibrated first.
- **No topology/roster evolution** — bodies and skills first; pattern/handoff-graph mutation is a v0.6 operator behind invariant 2.
- **No islands / MAP-Elites** — over-engineering for single-fleet scale; revisit if a fleet archive grows past ~20 lineages.
- **No second-order evolution** (PromptBreeder-style mutation of the mutation prompt) — prove the first-order loop.

## Phase 0 — Foundations

### T1 — Append-aware changelog

**Context.** `claudeMdPointer` (`src/adapters/claude-code.js:310-324`) and `agentsMdPointer` (`src/compile/pointers.js:12-35`) emit a hardcoded "Initial fleet build" changelog row with today's date. Verified: every rebuild clobbers whatever the orchestrator recorded there — yet `compileOrchestratorBody` step 3 (`src/compile/orchestrator.js:96`) instructs agents to "record the change in the harness changelog." The designated learning record destroys itself.

**Do.**
1. Move the changelog to `_fleet/CHANGELOG.md`, generated **once** (template with the initial row) and never overwritten on rebuild — same idempotency class as handoff files. Table columns: Date, Change, Target, Origin (`human|evolved`), Reason.
2. CLAUDE.md / AGENTS.md pointer sections keep a one-line link to `_fleet/CHANGELOG.md` instead of an inline table.
3. Update the orchestrator prose (`orchestrator.js:96`) and the harness-builder skill body to point at the new location.
4. Write-layer rule in `src/lib/fs-utils.js` / CLI: files marked `preserve: true` in the FileSet are written only if absent (no `--force` override without `--force-preserved`).

**Accept when** two consecutive `build --force` runs leave a manually-appended changelog row intact; `npm test` passes with a new test covering the preserve class.

### T2 — Spec provenance + skills vendored into the spec

**Context.** fleet.yaml has no `skills:` block — `validate` reports "4 agents, 0 skills" — while the four methodologies the meta-fleet depends on (`domain-decomposition`, `fleet-design`, `skill-authoring`, `harness-verification`) live untracked at user scope (`~/.claude/skills/`). A harness that rewrites its own skills cannot do it through the spec today. The loop also needs to distinguish what it may touch: nothing marks human vs machine authorship.

**Do.**
1. Add `origin: human|evolved` (default `human`) to `agents[]`, `skills[]`, and skill reference entries in `schema.js`; surface in compiled frontmatter as `x-fleetsmith-origin` so provenance survives into generated files.
2. Add `protected: true` (default for `origin: human`) — see T12 for enforcement.
3. Vendor the four user-scope skills into this repo's `fleet.yaml` `skills:` block (bodies + references), so `build` regenerates them at project scope and the compiler owns them. Keep user-scope copies as installs, not sources.
4. Wire `skills:` lists onto the four meta-fleet agents so `permission.skill` (opencode) and skill frontmatter attachments compile correctly.
5. `docs/spec.md` + tests.

**Accept when** `fleetsmith validate fleet.yaml` reports 4 agents, ≥4 skills; `build --target all` emits the four SKILL.md files byte-stable across two runs; every generated artifact carries an origin marker.

### T3 — Typed mutation API + `fleetsmith patch`

**Context.** fleet.yaml is only written by `init` or by hand (G3), and `normalizeSpec` is lossy — re-serializing a normalized spec destroys the author's formatting and comments. The evolution loop needs a mutation surface that is (a) format-preserving, (b) restricted to a typed vocabulary so every change is classifiable and reviewable, (c) hard-blocked from protected paths.

**Do.**
1. New module `src/evolve/patch.js` operating on the `yaml` package's **Document** API (comment/format-preserving), never on the normalized object.
2. Typed op vocabulary (SkillOps + SkillMentor): `add-skill`, `update-skill-body`, `merge-skills`, `repair-skill`, `retire-skill`, `add-validator`, `update-agent-body`, `add-playbook-bullet`, `update-bullet-counter`, `contract-change`. Each op: JSON with target path, payload, rationale, confidence, evidence refs (run ids / eval ids).
3. `contract-change` (anything under `agents[].handoff` or `skills[].triggers`) is a separate op class: rejected unless `--allow-contract-change`, never auto-applied (invariant 2).
4. Every op application: refuse targets with `origin: human`/`protected: true`; then `normalizeSpec` + `validateSpec` on the result; on failure, atomic rollback of the document.
5. CLI: `fleetsmith patch <fleet.yaml> --ops ops.json [--dry-run]` printing a unified diff; `--dry-run` is the default when stdin is not a TTY.
6. Retired skills follow the Hermes aging rule: renamed with a `_retired` suffix, removed only by a human.

**Accept when** a round-trip patch (add bullet, bump counter) produces a git diff touching only the intended lines, comments intact; ops against protected targets exit non-zero with a clear refusal; `npm test` covers every op type.

## Phase 1 — OBSERVE

### T4 — Run telemetry: run ids + `_fleet/runs/` events

**Context.** G1/G2: no run id, timings, cost, retries, or gate history anywhere. The richest untapped signal is the `SubagentStop` gate (`src/adapters/claude-settings.js:80-160` generates `_fleet/scripts/validate-handoff.sh`) — it already computes, per agent per stop, whether the handoff was complete, and discards it on `exit 2`. File-based JSONL is the substrate (git-diffable, no service); borrow OTel GenAI vocabulary so a future exporter is a mapping, not a rewrite (conventions still unstable as of 2026-07 — do **not** add the dependency).

**Do.**
1. Generate `_fleet/scripts/log-event.sh`: appends one JSON line to `_fleet/runs/current/events.jsonl` (creates dir; `current` is a symlink or id file set at run start). Fields: `ts`, `run_id`, `event` (`run_start|phase_start|invoke_agent|gate_pass|gate_block|execute_tool_error|run_end|evaluation`), `agent`, `detail`, optional `gen_ai.evaluation.result`-shaped `{name, score, explanation}`.
2. Instrument the generated `validate-handoff.sh`: on every decision, call `log-event.sh` with `gate_pass`/`gate_block` + agent + missing sections. This is free signal on Claude Code; opencode/goose get the same script invoked via orchestrator instructions (advisory but structured).
3. Orchestrator playbook (`orchestrator.js`): Phase 0 mints `run_id` (timestamp + fleet name) and logs `run_start`; each phase logs `phase_start`; Completion logs `run_end` with outcome. Keep instructions terse — one command per point, copy-pasteable.
4. Rotate: `_fleet/runs/<run_id>/` per run; never delete old runs (replaces the single-generation `_fleet_prev/` memory for telemetry purposes; handoff archival unchanged).
5. Ledger stays human-readable; runs JSONL is the machine record. Do not put per-run state in any prompt body (invariant 7).
6. *(Stretch, G10)* claude-workflow adapter: emit `log()` + a results-dump step writing phase results into the same events.jsonl, making the workflow target the richest OBSERVE source.

**Accept when** a meta-fleet build on Claude Code yields an events.jsonl containing `run_start`, ≥1 `gate_*` event with agent attribution, and `run_end`; the gate still blocks/permits exactly as before (existing tests unchanged).

### T5 — `fleetsmith health`

**Context.** Raw events need aggregation into decision-grade signals. SkillOps' five health metrics are designed for exactly our artifact type and require zero task-time LLM calls; Anthropic's skill diagnostics (never-loaded files, overused sections) are equally free.

**Do.**
1. `fleetsmith health [dir]` reads `_fleet/runs/*/events.jsonl` + the compiled harness and writes `_fleet/health.json`: per skill/agent — **Utility** (fraction of recent runs where the agent's gate passed first try / skill was loaded and its run succeeded), **Redundancy** (near-duplicate skill bodies via token-overlap similarity — no embedding dependency), **Compatibility** (handoff edges whose artifact contracts match), **Failure-Risk** (gate-block + retry rate from logs), **Validation-Gap** (skill has no eval cases / agent handoff has no criteria).
2. Compute ΔH vs the previous health.json; print "no maintenance needed" and exit 0 fast when ΔH < threshold (SkillOps early exit — the loop must be free at steady state).
3. Human-readable table to stdout; JSON to file. No LLM calls.

**Accept when** health.json regenerates deterministically from a fixture runs directory; ΔH early exit path covered by a test.

### T6 — Feedback capture

**Context.** G9: the end-of-run feedback question (`orchestrator.js:96`) and its routing (skill vs agent vs orchestrator) are prose — nothing records the question, the answer, or whether the routed change happened. Human corrections are the highest-signal, lowest-cost fitness source available.

**Do.**
1. Orchestrator Completion step: after asking the feedback question, log it via `log-event.sh` as `{event: "feedback", route: "skill|agent|orchestrator|none", text, agent}` — one command, appended to the same events.jsonl (single capture path, T13's decision log handles accept/reject learning).
2. `fleetsmith health` folds feedback counts into Failure-Risk.

**Accept when** a run with feedback produces the event; health output surfaces it.

## Phase 2 — EVALUATE

### T7 — `fleetsmith eval`: the missing runner

**Context.** G7: `src/compile/evals.js` emits trigger corpora and `cases: []` with no runner, scoring, or baseline — and Anthropic's guidance confirms you build your own. Without this there is no objective signal that a mutation improved anything; the loop would optimize against agent self-assessment, which `orchestrator.js:129` itself warns against. Small-N statistics rules: below ~30 cases, noise is indistinguishable from regression; run the incumbent twice first; use paired deltas.

**Do.**
1. `fleetsmith eval <fleet.yaml> [--stage 1|2|3] [--target claude-code] [--baseline <dir>]`:
   - **Trigger tests** (deterministic, free): for each skill, check `should_trigger` phrases hit the skill description and `should_not_trigger` miss, using the same matching heuristics as the lint budgets. Always run.
   - **Case tests**: execute `cases[]` in fresh headless sessions (`claude -p` / `opencode run` / `goose run --recipe`), grading `expected_behavior` by deterministic assertions where declared (file exists, section present, validator passes) — LLM grading only where a case explicitly opts in.
2. DGM staged ladder: stage 1 = smoke (≤3 cases, does the fleet still build + orchestrate), stage 2 = ~10 cases, stage 3 = full suite. Candidates must clear stage N before spending on N+1.
3. Noise floor: `--calibrate` runs the incumbent twice and records per-case variance to `_fleet/evals/noise.json`; deltas below the floor are reported as "no signal", never as wins.
4. Paired comparison: with `--baseline`, score the same case list on both harnesses and report paired deltas + pass^k (consistency), not just pass@k.
5. Results appended as `evaluation` events (`gen_ai.evaluation.result` shape) into the current run.
6. Seed the meta-fleet's eval set: 5–10 held-out fleet-build tasks (small domains with known-good expected properties) under `test/eval-fleets/`. **This directory is part of the protected set (T12) — the loop may add cases via proposal, never edit or remove existing ones.**

**Accept when** `fleetsmith eval` runs stage 1 green on the meta-fleet; a deliberately broken skill description fails its trigger tests; paired mode reports a delta with noise-floor annotation.

### T8 — `fleetsmith qa`: programmatic verification battery

**Context.** G8: the `harness-verification` skill's battery (spec gate, per-target compile cross-checks, handoff dead links, trigger tests, capability-leak grep, loop bounds) is prose executed by an agent, and the only enforced gate (`SubagentStop`) is Claude Code-only. Deterministic gates must live in the CLI so they are target-independent and CI-runnable — the verifier is the ceiling of the whole system (invariant 4).

**Do.**
1. `fleetsmith qa <fleet.yaml> [--built <dir>]`: port every deterministic check from the harness-verification skill into `src/qa/`: validate + lint; compile all targets in-memory and cross-check agent/skill/handoff parity per target; handoff-graph dead links and orphans (beyond current validate.js coverage: check *compiled* files, not just spec); capability-leak grep over generated files; loop-bound presence; drift detection — recompile the spec and diff against `--built` directory (the skill's "detect drift" primitive, now exact).
2. Exit non-zero on any FAIL; output PASS/FAIL per check with file:line evidence (same verdict format the skill promises).
3. GitHub Action: `qa` + `npm test` + `eval --stage 1` on every PR touching `fleet.yaml`, `src/`, or generated dirs.
4. The harness-qa *agent* keeps the judgment-call checks (methodology substance, decomposition quality); its skill body is updated to call `fleetsmith qa` for the mechanical battery instead of re-deriving it.

**Accept when** `fleetsmith qa fleet.yaml --built .` passes on a fresh build, fails with file:line evidence when a generated agent file is hand-edited (drift), and the Action runs green on this milestone's PR.

### T9 — (Optional) advisory skill-substance judge

**Context.** The one axis deterministic checks can't score: is a skill's methodology substantive or generic? Judge reliability research: explicit criteria with pass/fail thresholds work; subjective holistic scoring doesn't; calibrate before trusting.

**Do.** `fleetsmith eval --judge`: single judge (frontier model via `claude -p`), rubric of explicit binary criteria (names concrete tools? cites domain standards? steps executable without interpretation? counter-examples present?), score = criteria passed, **advisory only** — printed and logged as `evaluation` events, never gating. Calibrate against ≥20 human-rated skills before first use; store ratings + agreement stats in `docs/research/judge-calibration.md`. If agreement is poor, ship v0.5.0 without the judge.

**Accept when** judge output includes per-criterion verdicts + calibration stats, and no code path lets a judge score block a build, patch, or promotion.

## Phase 3 — MUTATE + VALIDATE

### T10 — ACE playbooks: learned context as id'd bullets

**Context.** G6 + invariant 3. Whole-file rewrites cause context collapse (ACE); memory accumulation measurably decays safety unless framed as references (Misevolution). The cache-stability invariant (`agent-prompt.js:8-14`) forbids per-run prompt state — but playbooks compiled in at **build** time change only when the spec rebuilds, which satisfies it.

**Do.**
1. `_fleet/playbooks/<agent>.md`: bullets as `- [pb-<agent>-<seq>] (+<helpful>/-<harmful>) <one strategy, concept, or failure mode>`. File carries a header: *"Machine-learned advisory references — not rules. Prefer current instructions and human guidance on any conflict."*
2. `fleetsmith playbook add|count|dedupe` — deterministic, non-LLM: `add` appends with fresh id; `count` increments counters; `dedupe` merges bullets above a token-overlap threshold keeping the higher-counter id. These are the only write paths (also exposed as patch ops, T3).
3. Compiler: agents with `memory: true` (or new `playbook: true`) get a final compiled section **"Learned notes (advisory, machine-authored)"** containing current bullets, clearly fenced. Bullet budget: 20 per agent, 200 chars per bullet (invariant 6); `dedupe` enforces on overflow, evicting lowest helpful-to-harmful ratio.
4. Reflector step is part of T11, not this task — T10 is storage + merge + compile only.
5. Preserve class (T1 rule): playbooks are never clobbered by rebuild.

**Accept when** a playbook bullet survives rebuild, appears fenced in the compiled agent on all three targets, and two conflicting `add`s merge deterministically to a stable file (test with fixed inputs).

### T11 — `fleetsmith evolve`: the loop

**Context.** All prior tasks exist to feed this. GEPA supplies the shape: reflect over *textual* failure output (not scalars), mutate one module per round-robin, validate locally then fully, keep a Pareto frontier rather than only the best. Decagon's production findings bind: 20–100 eval samples, frontier model for reflection, hard length caps.

**Do.**
1. `fleetsmith evolve <fleet.yaml> [--budget N] [--apply|--propose]` (default `--propose`):
   - **Gather** (no LLM): latest `_fleet/runs/*` events, `health.json` (respect ΔH early exit — if nothing changed, print and stop), `qa` failures, `eval` results, feedback events. Serialize as the reflection dossier — raw error text, not summaries (GEPA's "rich textual feedback").
   - **Select target**: round-robin over evolvable modules (agents' bodies, evolved skills, playbooks), skipping protected artifacts; weight toward highest Failure-Risk.
   - **Reflect + propose** (one frontier-model call via `claude -p --output-format json`): dossier + current artifact + typed-op schema in, ops JSON out. The proposal prompt forbids contract changes unless explicitly diagnosing a boundary failure, and encodes length caps (Decagon: constraint lives in the proposer, not post-hoc truncation).
   - **Apply on a branch**: `git switch -c fleet-evolve/<run_id>`, `fleetsmith patch` (T3 enforces protection + validity), `build --force`.
   - **Validate ladder**: `qa` (must pass) → `eval --stage 1` (must pass) → `eval --stage 2 --baseline <main build>` (paired delta must exceed noise floor). Any failure: record as `evolve_rejected` event with full text (the failure corpus is training signal — record failures, not just passes), delete branch, stop or move to next candidate within budget.
   - **Survivors**: keep the branch, write `_fleet/evolution/proposals/<run_id>.md` — diff, op types, rationale, confidence, eval deltas, evidence links — ranked if multiple.
2. Pareto archive: tag promoted specs `fleet-gen/<n>`; selection for future seeding samples across tags best-per-eval-case, not just latest (DGM archive; keeps specialists alive).
3. `--apply` auto-merges **only** when every op is in the auto-apply whitelist (T13) and all gates passed.

**Accept when** on a fixture project with a seeded failing run + failing eval, `evolve --propose` produces a branch whose diff touches only evolvable artifacts, a proposal doc with eval deltas, and leaves `main` untouched; with an empty dossier it exits early at ΔH.

### T12 — Safety rails: protected paths, CI diff guard, caps

**Context.** Invariants 1, 5, 6 need enforcement outside the loop's own runtime — any control inside the agent's runtime is reachable by inputs that influence the agent. Two independent layers: the patch API (T3, in-process) and CI (out-of-process).

**Do.**
1. `_fleet/evolution/protected.json`, generated from the spec (`origin: human` / `protected: true`) **plus hard-coded entries the spec cannot unprotect**: `src/spec/**`, `src/qa/**`, `src/evolve/patch.js`, `test/**`, `test/eval-fleets/**`, `_fleet/scripts/validate-handoff.sh`, `.github/workflows/**`, this file and both research docs.
2. CI job on every `fleet-evolve/*` branch: `git diff --name-only main...HEAD` must be a subset of allowed paths; any protected hit fails the build with the DGM marker-removal story in the error message (so future maintainers don't "simplify" it away).
3. Length caps enforced at patch time: SKILL.md ≤500 lines, agent body ≤300 lines, bullet rules per T10; oversize ops rejected with the cap in the error.
4. `fleetsmith qa` check: every generated file's origin marker matches the spec's `origin` — catches laundering of machine content into human-marked artifacts.

**Accept when** an evolve branch touching `test/eval-fleets/` fails CI; an op targeting a protected skill is refused in-process; both layers are covered by tests that would scream if either is deleted.

## Phase 4 — PROMOTE

### T13 — Promotion pipeline + decision learning

**Context.** Staged promotion (shadow → canary → full) adapted to a CLI tool; git is the ladder. HITL design must avoid automation bias: few, ranked, confidence-scored asks; the system learns which categories the user rejects (claude-improve's learnings-file mechanism — the improver learns which of its own suggestions are worth making).

**Do.**
1. `fleetsmith evolve --review`: presents surviving proposals ranked by (eval delta × confidence), one at a time — Accept / Reject / Modify. Accept = merge branch to main + tag `fleet-gen/<n>` + append `_fleet/CHANGELOG.md` row (`Origin: evolved`). Reject = branch deleted, reason captured.
2. Every decision appended to `_fleet/evolution/decisions.jsonl` (op types, target, confidence, verdict, reason). The evolve proposal prompt receives a digest of recent decisions and deprioritizes op/target categories with high rejection rates.
3. Auto-apply whitelist (no human ask): ops fully verifiable deterministically — `update-bullet-counter`, `merge-skills` on hash-identical bodies, `add-validator`, `retire-skill` at Utility < 0.05 over ≥10 runs (SkillMentor eviction). Everything else queues for `--review`.
4. Canary semantics: a merged generation is provisional until the next N real fleet builds complete without gate-block regression vs `health.json` baseline; `fleetsmith health` prints canary status; regression → `git revert` of the generation tag is the documented (and tested) rollback.
5. Optional cadence: document a weekly `evolve --propose` invocation for Claude Code (`.claude/loop.md` pattern) and cron for goose — never autonomous `--apply` outside the whitelist.

**Accept when** an accept and a reject both round-trip into decisions.jsonl; a whitelisted counter-bump auto-applies with no prompt; `git revert <tag>` restores the prior harness and `qa` passes on the result.

### T14 — Docs, dogfood, release

**Do.**
1. `docs/spec.md`: `origin`, `protected`, `playbook`, evolution section. New `docs/evolution.md`: the five-stage loop, the eight invariants, op vocabulary, promotion ladder, rollback procedure.
2. README: "Self-evolution" section with the honest framing — deterministic gates carry everything; judges advisory; human reviews contract changes.
3. Dogfood: run the full loop on fleetsmith's own meta-fleet — at least one complete OBSERVE→PROMOTE cycle with a real accepted proposal and a real rejected one; record both in `_fleet/evolution/decisions.jsonl` and the changelog.
4. CHANGELOG.md (repo) entry; bump to 0.5.0; verify `npm test`, `fleetsmith qa`, `eval --stage 2` all green; tag.

**Accept when** a zero-context agent can execute one evolution cycle following only docs/evolution.md, and the release checklist is green.

## Risks and mitigations

| Risk | Evidence | Mitigation |
|------|----------|------------|
| **Misevolution** — accumulated learned content degrades behavior/safety with no attacker | Refusal-rate drops of 45–86% measured across memory/tool/workflow evolution on frontier models (arXiv 2509.26354) | Invariants 1–3; advisory framing; separate machine-authored regions; caps; eviction |
| **Reward hacking the gate** | DGM removed the detection markers it was scored on | Gates live outside evolvable paths (T12 two layers); eval fleets immutable to the loop |
| **Verifier bottleneck** — loop quality capped by `qa`/`eval` quality | arXiv 2607.07663 | Invest T7/T8 before T11; judges never gate; treat verifier bugs as safety bugs |
| **Noise mistaken for improvement** on small eval sets | <30 cases ⇒ noise ≈ signal | Noise-floor calibration, paired deltas, pass^k, staged ladder |
| **Reviewer rubber-stamping** | Automation-bias literature; flooding decays HITL | Few ranked asks; auto-apply whitelist; rejection learning |
| **Overfit, bloated prompts** | Decagon: more data → worse; unconstrained GEPA → 5,000-char prompts | 20–100 eval cases; hard length caps in the proposer |
| **Cross-target enforcement asymmetry** | Only Claude Code blocks at `SubagentStop` | All promotion gates run in the CLI/CI (target-independent); per-target hooks are bonus signal, not the gate |
| **Loop cost at steady state** | — | ΔH early exit (free when nothing changed); staged ladder; one reflection call per cycle |
