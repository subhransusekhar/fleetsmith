# Milestone v0.7.0 — Intelligence Grid (Enterprise Multi-Developer Sync)

**Status:** planned · **Created:** 2026-08-15 · **Owner:** unassigned · **Depends on:** v0.6.x (M1 memory port, M2 file backend), `docs/architecture/multi-user-context.md`, `docs/research/relatadb-memory-backend-2026-08.md`

## Purpose

Give an enterprise team running fleetsmith harnesses **in the same repo** a shared cloud cortex, backed by a customer-supplied RelataDB (BYOL), so that:

1. **Agent memory syncs between developers before any git commit** — lessons, decisions, and notes recalled semantically across the team, not just after a PR merges the shared tier.
2. **Each developer's agents know what every other developer is working on right now** — live task/ledger state, files being touched, artifact contracts in flight — so agents can reuse functions instead of duplicating them, declare dependencies on in-flight work, and anticipate merge conflicts and post-staging bugs before they happen.
3. **Organizational intelligence feeds the harness** — client meeting notes, group calls, product discussions are ingested and become recallable context for agent decision-making.
4. **The enterprise governs the grid** — developer harnesses inside a project are governed by a central cortex: policy, purpose registry, tenancy, audit, and a controlled promotion path for learned knowledge.

**Theme: the file is still the truth.** The grid never replaces the handover protocol — it *projects* it. The precedence rule from `src/handover/protocol.js` ("the message is a doorbell; the file is the payload") extends verbatim: **the grid is a doorbell network; local files remain the payload and the authority.** Every grid capability degrades to the file backend + git with one warning and zero run failures (v0.6.0 rule 3).

**Packaging: open-core with an `ee/` tree.** Every feature in this milestone ships under `ee/` — its own subtree, its own `ee/LICENSE` (**AGPL-3.0-only**), its own npm package (`fleetsmith-ee`). The core repo and the `fleetsmith` package stay MIT with one runtime dependency, and core never imports from `ee/`: enterprise code registers itself through a small plugin registry (G0). Deleting `ee/` must leave core exactly at v0.6 behavior — the same property that already protects us from vendor risk now also draws the license boundary.

**Legal posture (supersedes the v0.6.0 M7 gate):** ZySec AI is an Infinia group company, so trademark permission, license-stability assurance, and pricing coordination are internal alignment rather than external legal risk. The M7 gate on public release is dissolved; what remains in G10 is intra-group coordination (naming sign-off, license-ops for containers, upstream changefeed request). The three BYOL engineering rules stand unchanged — never vendor the binary, never patch the engine, always degrade to file — because they are architecture, not legal caution.

## What v0.6.0 already settled (do not re-litigate)

- Memory port exists (`src/memory/port.js`): `remember / recall / consolidate / forget / justify`, `purpose` mandatory on recall, `runContract()` is the acceptance suite for any backend.
- File backend is the default and only bundled backend, forever. No capability may be backend-only — grid features must have a degraded git-based answer.
- BYOL, three non-negotiable rules (never vendor the binary, never patch the engine, always degrade to file), CI-enforced.
- The M7 legal gate is **dissolved** by group structure (ZySec AI is an Infinia company — see legal posture above); its checklist survives as G10 coordination items.

## What the RelataDB v2.0.0 source audit adds (2026-08-15)

Read alongside `docs/research/relatadb-memory-backend-2026-08.md`. Facts that shape this design:

| Finding | Design consequence |
|---|---|
| `/memory/*` writes bypass `governed_upsert` and therefore **never appear on the `/graph/changes` SSE changefeed** (`crates/relata-cli/src/serve/mcp/memory.rs:346`) | Agent *memory* goes through `/memory/*`; **task/presence/handoff state goes through `/ingest` as our own ontology types**, which does get WAL + ACL + SSE fan-out |
| `LIMIT n AFTER '<system_from_ns>'` cursor pagination on `_system_from` | This is the incremental-sync primitive; SSE is only the wake-up signal |
| `/watch/stream` is a stateless per-request poll that re-executes every registered watch (O(watchers × query cost), in-process registry, lost on restart) | Unusable at fleet scale; do not build on it |
| No CRDTs; bi-temporal supersession + HLC ordering, no automatic merge | Design for **single-writer rows**: every grid row is keyed by actor, so concurrent developers never write the same row. Merge is a non-problem by construction |
| Multi-tenant = **cluster profile + paid license**; `server`/`free` are hard-pinned `max_tenants=1`; sub-tenant namespaces parsed but **not enforced** (#54); single-tenant reads are unscoped across org headers | One tenant = one enterprise org (or one project on a dedicated instance). Per-developer identity is carried as **principal + `actor` field**, never as tenant or namespace |
| Embeddings are caller-supplied since v1.1; embedder sidecar (`RELATA_ACCEL_ENDPOINT`) is the supported path; without it, semantic recall falls back to BM25/Jaccard | v0.7.0 ships **text-only (BM25 + RRF) by default**; the sidecar is a documented customer-side option, keeping the one-dep promise |
| Conditional ACL policies not yet wired into every call site (#3118/#3125/#3126); Cedar integration deferred | Treat cell-level ACL as **defense in depth**, not the sole isolation boundary; don't put secrets in grid rows |
| Session draft writes (`/session/:id/{draft,diff,commit}`) are in-memory, TTL-evicted | Not a durability primitive; ignore for v0.7.0 |
| Bearer tokens with TTL/rotation/mid-stream revocation; OIDC JWT (RS256/ES256 + JWKS) | Enterprise auth story is real; grid daemon authenticates per developer |

## Architecture

```
  developer A laptop                          developer B laptop
┌─────────────────────────┐                 ┌─────────────────────────┐
│ fleet agents            │                 │ fleet agents            │
│   │ read/write (files)  │                 │                         │
│ _fleet/local/           │                 │ _fleet/local/           │
│   LEDGER.md  handoffs/  │                 │   LEDGER.md  handoffs/  │
│   runs/  notes/         │                 │   grid/peers/A/  ◄──────┼── read-only projection
│   grid/peers/B/  ◄──────┼── of B's work   │                         │
│         ▲               │                 │         ▲               │
│  fleetsmith grid sync   │                 │  fleetsmith grid sync   │
└───┬─────┴───────────────┘                 └───┬─────┴───────────────┘
    │ push: /ingest (typed rows)                │
    │ pull: SSE /graph/changes + cursor         │
    ▼                                           ▼
┌──────────────────────────────────────────────────────────────────┐
│                RelataDB (customer-run, BYOL)                     │
│  grid ontology: FleetTask · ActorPresence · HandoffPointer ·     │
│                 RunEventSummary                                  │
│  memory verbs:  MemoryItem · ProcedureMemory · DecisionRecord    │
│  org knowledge: OrgDocument (meetings, calls, discussions)       │
│  governance:    purpose registry · ACL · audit chain · AS OF     │
└──────────────────────────────────────────────────────────────────┘
                        ▲
        fleetsmith grid import  (meeting notes, transcripts)
```

Sync unit boundaries, restated from `multi-user-context.md` and unchanged:
- `_fleet/local/` is **never synced wholesale** — the grid carries a *projection* (ledger rows, handoff pointers, event summaries), not the run directories.
- `_fleet/shared/` promotion still goes through the PR ladder. The grid does not create a second trust path for team knowledge; it creates a *faster advisory path* whose contents are visibly machine-carried and never merged into shared without review.

## G0 — `ee/` open-core scaffolding

**Context.** The license boundary must exist before any enterprise line is written, or ee code leaks into MIT history. Model: everything under `ee/` is AGPL-3.0-only; core stays MIT and structurally ignorant of ee.

**Do.**
- `ee/` subtree: `ee/LICENSE` (verbatim GNU AGPL-3.0), `ee/README.md` (what lives here, why the license differs, how it loads), `ee/package.json` (`fleetsmith-ee`, `license: "AGPL-3.0-only"`, peer-dep on `fleetsmith`), `ee/src/`.
- Plugin registry in core (MIT): `src/lib/registry.js` — `registerMemoryBackend(name, factory)`, `registerCliCommand(name, handler)`, `registerDaemonHook(event, fn)`. Core resolves backends/commands through the registry; the file backend registers itself the same way, so the seam is exercised on every OSS run.
- Loader: the CLI attempts `import('fleetsmith-ee')` (or `FLEETSMITH_EE_PATH`) at startup, fail-soft and silent when absent. The ee entrypoint's only job is to call registry functions.
- Packaging: `fleetsmith` npm `files` already excludes `ee/`; `fleetsmith-ee` publishes from the subtree. One repo, two artifacts, two licenses.
- CI guards: (a) no `ee/` import anywhere under `src/` (the loader's dynamic specifier is the sole exception), (b) every file under `ee/src/` carries the AGPL SPDX header, (c) the existing no-vendoring check runs over `ee/` too.

**Accept when** `rm -rf ee/` leaves the full v0.6 test suite green and the CLI byte-identical in behavior; with ee installed, `fleetsmith --version` lists the ee package and its license; CI fails on a seeded `src/ → ee/` import.

## G1 — RelataDB memory adapter

**Context.** v0.6.0 M3, scope unchanged; this milestone finally builds it. ~200 lines of native `fetch` in `ee/src/memory/relatadb.js`, registered via the G0 registry, implementing the port against `POST /memory/remember`, `POST /memory/remember/batch`, `GET /memory/recall` (with `purpose`, `top_k`, `session_id`, `min_confidence`, `recency_half_life_secs`, `budget_tokens`), `consolidate`, `forget`, `justify`. Gated on `RELATA_URL` + `RELATA_TOKEN`; text-only (no embeddings) per the v0.6.0 recommendation.

**Do.**
- Map port kinds → `memory_class`: lesson→`procedural` (via `remember_procedure`, preserving `supersedes` chaining — v0.6.0 M4 folds in here), decision→`DecisionRecord`, note→`semantic`. Events remain refused through the port (single-writer rule); their grid story is G3's `RunEventSummary`.
- Carry `origin: human|evolved`, evidence list, and helpful/harmful counters as row fields; `actor` from the v0.5 resolution chain (`FLEETSMITH_ACTOR` → git email local part → `$USER`).
- Batch writes through `remember/batch` (the amortized-FTS path); single-item writes only for interactive verbs.
- Degrade to file backend on connection failure, 4xx license exhaustion, or exit-78 symptoms — one warning, run completes (CI-tested by killing the instance mid-contract-suite).

**Accept when** `runContract()` passes against a live v2.x instance; mid-run instance kill degrades with a warning and the run completes; CI asserts no RelataDB code is vendored; recall results on both backends satisfy the same contract shape.

## G2 — Grid ontology

**Context.** The changefeed caveat forces this split: anything other developers must *see live* is written as our own typed rows through `/ingest` (→ `governed_upsert` → WAL, ACL, `/graph/changes` SSE). Types auto-register on ingest; pin them with an explicit `/ontology/migrate` pack so the schema is reviewed, not accidental.

**Do.** Define four types, all **single-writer by key** (keyed on `actor` or `actor+seq`, so no two developers ever contend on a row — concurrency by construction, not by merge):

| Type | Projected from | Key fields |
|---|---|---|
| `FleetTask` | `_fleet/local/LEDGER.md` rows | actor, task, status, depends_on, artifact path, files_declared[], symbols_declared[] |
| `ActorPresence` | `CURRENT-<actor>` + run start/end | actor, run_id, branch, started_at, heartbeat_at |
| `HandoffPointer` | `_fleet/local/handoffs/*.md` | actor, seq, from, to, artifact path, criteria digest — **pointer + digest, never the handoff body** (contents stay local; the grid carries the doorbell) |
| `RunEventSummary` | `runs/<run>/events.jsonl` reduced by the health reducer | actor, run_id, per-agent gate_pass/gate_block/error counts |

- Every row carries `purpose`, `origin`, branch name, and repo identity (remote URL hash) so one cortex serves many projects.
- `files_declared` / `symbols_declared` come from the ledger row's artifact column plus a cheap `git diff --name-only` + tree-sitter-free symbol grep at push time; declared best-effort, consumed advisory (G5).
- Ship as a fleetsmith-owned pack (`packs/grid/types.toml` equivalent) applied by `fleetsmith grid init`.

**Accept when** the ontology migrates cleanly on a fresh instance, every type round-trips through `/ingest` → SQL query → row, and each write from a second actor lands as a distinct row (no cross-actor row contention under concurrent push).

## G3 — `fleetsmith grid` daemon

**Context.** The sync engine. Push side projects local state up; pull side materializes peers' projections down into `_fleet/local/grid/peers/<actor>/` as plain markdown/JSONL that agents read like any other file — no agent ever talks to RelataDB directly for grid state, which keeps the harness working identically across Claude Code, opencode, and goose.

**Do.**
- `fleetsmith grid sync [--watch]`: one-shot or daemon. Push: diff local ledger/handoffs/CURRENT against last-pushed digests, `/ingest` changed rows. Pull: subscribe SSE `/graph/changes?type=FleetTask,...` as wake-up; on wake (and on a slow-subscriber gap notice, and every N minutes regardless), reconcile via `SELECT … LIMIT n AFTER '<cursor>'` on `_system_from`; persist the cursor in `_fleet/local/grid/cursor`.
- Materialize per peer: `_fleet/local/grid/peers/<actor>/LEDGER.md` (same table shape as the local ledger), `presence.json`, `handoffs.md` (pointer list). Plus one rollup the orchestrator can read in a single breath: `_fleet/local/grid/GRID.md` — active actors, their in-progress tasks, declared files/symbols, staleness timestamps.
- Trigger points: hook into existing seams only — `run_start`/`run_end` via `log-event.sh` (fail-soft, advisory, never gating), plus the daemon's watch loop. **The SubagentStop gate is untouched** — `validate-handoff.sh` is on the protected-paths list and stays there; grid sync must never become a condition for an agent to finish.
- Heartbeat + staleness: presence rows older than a TTL render as `(stale)` in GRID.md; never delete peers' rows, supersede them (bi-temporal close) on run_end.
- Offline/degraded: no `RELATA_URL`, unreachable, or license-expired → daemon exits 0 with one warning; `grid/peers/` keeps last-known state with staleness marked; everything else proceeds file-only.

**Accept when** two checkouts (two actors, one instance) see each other's ledger rows in `grid/peers/` within seconds of a push without any git commit; killing the instance mid-watch leaves both harnesses fully functional with stale-marked grid files; the cursor survives daemon restart with no missed or duplicated rows (idempotent upsert by row key).

## G4 — Awareness surfaces

**Context.** Sync without consumption is plumbing. Agents must actually *read* the grid at the moments that matter: task selection, artifact contract design, and pre-handoff.

**Do.**
- Extend `protocolBlock()` (`src/handover/protocol.js`) with a grid section, compiled only when the fleet has grid enabled: *"Before claiming a task, read `_fleet/local/grid/GRID.md`. If another actor's in-progress task declares files or symbols overlapping yours, say so in your handoff's Context digest and prefer depending on their declared artifact over re-implementing it. Grid state is advisory and may be stale — the files in this checkout are the truth."* Cache-stability invariant holds: the prompt references the *path*, never run-varying content.
- New compiled skill `grid-awareness` (emitted once into `.claude/skills/`, read natively by all three targets): methodology for interpreting GRID.md — staleness rules, how to phrase a cross-actor dependency in a ledger row (`depends on: @<actor>#<task-seq>`), when to recall team memory (`purpose: cross_dev_reuse`) before writing a new utility.
- Ledger gains the cross-actor dependency notation above; `fleet-status` (opencode command) and the statusline read GRID.md for a one-line "3 actors active, 1 overlap" summary.

**Accept when** a compiled agent, given a GRID.md showing a peer mid-task on an overlapping file, mentions the overlap in its handoff Context digest and declares the dependency in its ledger row (eval-fleet test); with grid disabled or stale, prompts compile identically to v0.6 (drift check passes).

## G5 — Overlap intelligence

**Context.** The proactive half of the ask: reuse detection ("two developers are about to write the same helper"), dependency awareness, and merge/staging risk anticipation. Deterministic checks first (the project's standing invariant: deterministic checks carry every gate); model judgment stays advisory and inside existing agent turns — no new model call in the loop.

**Do.**
- `fleetsmith grid overlaps` (also run by the daemon after each reconcile): pure-function comparison of all active `FleetTask` rows — file-set intersections, symbol-name collisions (normalized), artifact-path collisions, and dependency cycles across actors (A depends on B's task which depends on A's). Output: `_fleet/local/grid/OVERLAPS.md`, severity-ranked, each row citing both actors' tasks.
- Merge-risk anticipation: for each pair of active branches, `git merge-tree` (available locally, no commit needed — branches are pushed or fetched normally) against the staging base where refs exist; where they don't, fall back to declared-file intersection. Findings land in OVERLAPS.md as `merge-risk` rows: same-file edits, deleted-vs-modified, adjacent-region edits.
- Future-bug anticipation is framed honestly: it is the *recall* path, not an oracle — before an agent finalizes an artifact touching file X, `grid-awareness` has it recall (`purpose: regression_check`) lessons and past `RunEventSummary` failures mentioning X, plus any org-knowledge decisions (G6) constraining X. Ranked by RelataDB's confidence × recency; degraded backend answer is token-overlap over shared playbooks.
- Nothing here blocks anything. OVERLAPS.md feeds prompts and the statusline; humans and agents decide.

**Accept when** two eval-fleet actors declaring the same symbol produce a ranked OVERLAPS.md row within one reconcile cycle; a synthetic deleted-vs-modified branch pair produces a merge-risk row; the file-backend degradation still produces file-intersection overlaps from git alone (no RelataDB required for the deterministic core).

## G6 — Org knowledge ingestion

**Context.** Client meeting notes, group calls, product discussions become agent-recallable context — the "intelligence" in the grid. This is where RelataDB's governance actually earns its seat: provenance per document, purpose-gated recall, bi-temporal "what did we know when we decided X", cell-level masking for client-sensitive rows.

**Do.**
- `fleetsmith grid import <path|dir> --kind meeting|discussion|decision|spec [--client <name>] [--date <d>]`: chunks markdown/text/transcripts, writes `OrgDocument` rows via `/ingest` with `_emb_text` populated (used only if the customer runs the embedder sidecar; BM25 + RRF `HYBRID_SEARCH` otherwise), provenance = source file + importer identity, `valid_from` = meeting date (business time), system time = import time. Idempotent by content hash; dry-run by default (v0.6.0 M6 discipline).
- Recall path: through the existing memory port (`recall(query, {purpose})`) with registered purposes — `product_context`, `client_commitment`, `decision_rationale`. The port hides whether the answer came from team memory or org documents; agents just get ranked context with provenance strings they can cite in handoffs.
- File-backend degradation: `_fleet/shared/knowledge/*.md` (committed, PR-reviewed) with token-overlap recall — the OSS-tier answer, so the capability is not RelataDB-only.
- Explicit non-goal: fleetsmith does not transcribe calls or connect to Slack/Meet/Zoom in v0.7.0. Input is files; connectors are a customer-side ETL concern (documented pattern, not shipped code).

**Accept when** an imported meeting-notes corpus is recallable by purpose with document-level provenance on both backends; re-import creates no duplicates; `AS OF` on RelataDB answers "what did we know before <date>" (fuller answer than file, same contract shape).

## G7 — Central cortex governance

**Context.** "Developer harnesses governed by an enterprise harness in cloud." Concretely: identity, isolation, purpose discipline, audit, and a controlled downstream channel for org-approved knowledge — using RelataDB primitives where they're real, and refusing to build on ones that aren't (namespaces #54, conditional-policy gaps #3118).

**Do.**
- **Tenancy model, documented as the deployment decision tree:** one enterprise org = one tenant. Multi-project isolation *within* an org uses the repo-identity field + ACL, not namespaces. Multi-org (true multi-tenant) requires cluster profile + paid license — state this plainly, including the node-bound 24 h manual license issuance hazard for containerized deployments.
- **Identity:** each developer gets their own bearer token (TTL + rotation via `/tokens/self/rotate`); token principal must match the `actor` field on pushed rows (daemon enforces client-side; ACL policy enforces server-side where wired). OIDC/JWKS documented for SSO shops.
- **Purpose registry:** ship the standard purpose set (`cross_dev_reuse`, `regression_check`, `product_context`, `client_commitment`, `decision_rationale`, `grid_sync`) as part of `grid init`; every recall is purpose-tagged and lands in the audit chain — the compliance answer to "what did agents read and why".
- **Downstream governance channel:** the cortex can mark `ProcedureMemory` / `OrgDocument` rows `org_approved`. Approved rows rank above unapproved in recall and appear in a distinct GRID.md section — **but they remain advisory, and promotion into `_fleet/shared/` still requires the PR ladder.** One review path, no new trust model (multi-user-context.md's rule, kept).
- **Audit surface:** `fleetsmith grid audit --actor <a> --since <t>` wraps `/audit/entries` + `justify` — who pushed what, who recalled what under which purpose, and why a given memory exists.
- **Evolution stays local:** the evolve loop reads grid-attributed health (per-actor `RunEventSummary` sharpens the existing "fails for everyone vs fails for one setup" distinction) but proposes and promotes exactly as today. The cortex never mutates a developer's harness.

**Accept when** a second developer's token cannot write rows as the first (ACL test); recall audit answers actor/purpose/time queries; an `org_approved` procedure outranks an unapproved duplicate in recall on RelataDB while file-backend behavior is unchanged; a full grid deployment is configurable from docs alone on server profile (single org) and cluster profile (multi-org).

## G8 — Cortex admin console

**Context.** The enterprise face of the grid: a web console for admins and developers over the same REST surface the daemon uses. Prior art studied 2026-08-15: **TencentDB Agent Memory v2.0** (`TencentCloud/TencentDB-Agent-Memory`, MIT — MemoryPanel: React + stateless BFF over a metadata kernel). Its admin panel validates the shape of this product and, just as usefully, shows where it cuts corners we must not.

**Patterns borrowed** (with their source in the Tencent panel):

| Pattern | Adaptation for fleetsmith |
|---|---|
| **Loadout, not global recall** — assets are explicitly *equipped* onto agents; retrieval scope = team ∩ visibility ∩ bindings *before* any search | An **Equip screen**: which memory scopes, org-knowledge collections, and approved procedures each fleet/agent recalls from. Compiles down to purpose + ACL filters on the recall path — never a query-time hope |
| **Private-by-default, sharing is an explicit act** (kernel-enforced `ASSET_NOT_SHARED`) | Developer-local candidates stay private until explicitly proposed; enforced server-side by ACL, not by UI |
| **One-time-visible credentials** — key shown once, prefix-only listing, immediate revoke | Token screen for per-developer grid tokens (creates/rotates via `/tokens`), same one-time-visibility discipline |
| **Asset lifecycle status machines + "unready can't be equipped"** | Import/sync pipelines (G6 ingestion, G3 projections) surface queued/processing/ready/error with metrics strips; unready knowledge is unequippable |
| **Observed, not declared, activity** — task board shows who/which agents actually ran | The grid board *is* this: FleetTask/ActorPresence rows are projections of real runs, rendered as the live team board with staleness marks |
| **team/agent/task triple on every row** | Already ours as repo/actor/task — keep it universal across memory writes, grid rows, and audit entries |

**Anti-patterns to build against** (observed gaps in the same codebase): promotion there is a self-serve toggle with no review queue — ours gets a real state machine (`draft → proposed → approved → published`, reviewer-gated, diff-on-promotion), aligned with the PR ladder rather than replacing it. No audit UI despite rich backend telemetry — ours ships the audit screen in v1 (G7's `grid audit` rendered: who recalled what, under which purpose, when). Permission checks in the frontend only — every check server-side. Governance state stuffed into a JSON metadata blob — ours are first-class typed rows (they're already the G2 ontology). Silent governance degradation when session headers are missing — the console and daemon fail loudly or provision explicit defaults.

**Do.**
- Screens, in priority order: **Grid board** (live actors/tasks/overlaps — GRID.md's web twin), **Audit**, **Knowledge** (org documents: import status, provenance, approval state machine), **Procedures** (versioned playbooks with `supersedes` history, approve/deprecate), **Equip** (per-fleet/per-agent recall scopes), **Tokens & members**, **Deployment health** (instance status, license/tenancy, degradation state).
- Architecture copies the sound part: a thin stateless BFF over RelataDB's REST; no second database. The console is a *view + approval surface*; all state lives in the cortex, all mutations are audited rows.
- Ships as a separate enterprise package; fleetsmith core stays one runtime dep. The OSS tier's console is the files themselves (GRID.md, OVERLAPS.md) — stated plainly.

**Accept when** the approval state machine round-trips (propose from CLI, approve in console, `org_approved` visible in recall ranking); audit answers actor/purpose/time queries from the UI; every console mutation is enforced server-side (frontend-bypass test with raw curl); the console degrades to read-only when the caller's token lacks admin role.

## G9 — Degradation, security, CI guards

**Do.**
- Degradation matrix, tested: no config → pure v0.6 behavior; unreachable → stale grid + warning; license exit-78 → same; mid-SSE token revocation → reconnect with rotated token or degrade. In every row, runs complete and gates behave identically.
- Secrets hygiene: grid rows are pointers, digests, and metadata — never handoff bodies, never file contents, never env/config values. Enforced by a push-side redaction check (deny-list: values matching key/token/secret patterns) since server-side conditional ACL is not yet everywhere.
- CI: the existing no-vendoring check extends to the grid code; a contract-pin test asserts the six endpoints + cursor semantics the daemon relies on against a pinned RelataDB version, so an upstream breaking change fails our CI, not a customer's sync loop.
- One new invariant recorded in `docs/evolution.md`: **grid state is advisory input to prompts and health; it may never gate an agent, alter a verdict, or bypass the promotion ladder.**

**Accept when** the matrix is covered by tests, the redaction check blocks a seeded secret, and the contract-pin suite runs in CI against a containerized instance.

## G10 — Group coordination, docs, release
